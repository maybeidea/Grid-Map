# 局部 ESDF 更新与线程上限

高层、低层默认启用局部更新，默认最多 2 个 OpenMP 工作线程：

```yaml
grid_map.esdf_local_update: true
grid_map.omp_threads: 2
# 低层默认继承上面两项，也可以单独覆盖：
grid_map.low_esdf_local_update: true
grid_map.low_omp_threads: 2
```

配置在 `initMap()` 读取，修改后重启节点。小任务按工作量使用更少线程，不修改进程全局 OpenMP 设置。直接 C++ API 的 `EsdfConfig` 同样默认开启局部更新、上限 2。

## 更新机制

占据融合继续只修改射线穿过的体素。ESDF 每次触发计算时比较当前二值障碍源（含未知空间策略和高度带），找出改变的 Z 列；重算这些列后，仅中间平方距离改变的位置会激活下一阶段的 Y 行，再传播到 X 行。每条激活的行使用该轴的完整源数据，因此支持障碍新增、障碍删除、自由/未知切换及远处最近障碍的影响，与全量距离变换结果一致。

首次计算及缓存失效后建立完整 Z/Y 中间缓存；没有源变化时跳过距离变换。大范围变化可能传播至全图，不承诺固定更新盒尺寸。`esdf_local_update=false` 切换为变化时全量重算，`EsdfVolume::compute()` 仍保留强制全量计算接口；`computeIfChanged()` 遵循局部开关。

低层每个有效帧执行局部检查/更新。高层沿用站位提交和 `esdf_recompute_change_voxels` 阈值，到达阈值时局部更新；阈值下复用旧场仍明确标记 `esdf_current=false`。需要高层每次提交立即更新时设置 `grid_map.esdf_recompute_change_voxels: 0`。

## CPU 与内存

局部化的是距离变换；障碍源分类仍扫描整张体积，快照仍复制数组。signed ESDF 为正/负两套 Z/Y 中间结果保留 4 个 float 体积，共 16 字节/体素，另有 1 字节/体素的原有障碍掩码。初始化局部缓存时释放原来的全量临时距离缓冲；停止任务、重配置时清除局部缓存。对于实际约 21.57 万个双层体素，中间缓存约 3.29 MiB，比上一版 4 字节/体素的单临时缓冲多约 2.47 MiB。unsigned 模式只需两份中间体积。

## 合成基准

2026-10-23，同机 GCC 11.4 Release、2 线程上限，预热后每轮 30 次、3 轮均值取中位数。5% 随机障碍场，每次切换体素 0 的占用状态，比较同一个程序的 `esdf_local_update=false/true`：

| 体素数 | 全量墙钟 ms | 局部墙钟 ms | 全量累计 CPU ms | 局部累计 CPU ms | 最后一次变换行数：全量 → 局部 |
|---|---:|---:|---:|---:|---:|
| 125,000 | 4.030 | 0.475 | 8.063 | 0.612 | 15000 → 16 |
| 83,300 | 2.583 | 0.311 | 5.150 | 0.448 | 14560 → 22 |
| 1,360,000 | 43.724 | 5.460 | 84.790 | 5.640 | 107200 → 20 |

此稀疏变化场景墙钟降低约 88%，不代表整帧或实机能加速相同比例。多点变化、清除孤立障碍或初始化时会处理更多行。`lastUpdatedLines()` 可读出上次执行的一维变换行数。

编译时启用 `-DPLAN_ENV_BUILD_BENCHMARKS=ON`，运行 `OMP_NUM_THREADS=2 ./mapping_benchmark esdf 30` 复现；新增 `esdf_full_sparse_*` 和 `esdf_local_sparse_*` 两组。原始数据见 [local_update_results.csv](local_update_results.csv)。

构建算法库、ROS 库、两个节点、基准程序；33 项测试通过。新增覆盖稀疏变化、唯一障碍删除影响远处、均匀场/自由空腔、正负距离、未知高度带、可写访问和清空重建失效、局部与全图结果一致、局部实际减少变换行数，以及双层参数继承/覆盖。运行环境缺少 bimax_msgs，没有验证实际 HeightMap 发布分支；没有实机回放。
